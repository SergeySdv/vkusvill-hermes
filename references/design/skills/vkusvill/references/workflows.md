# Сценарии

## Подбор из списка — MVP

Сохранить требования → поиск кандидатов → детали финалистов → импорт локальной корзины → check → таблица и при запросе share link. Не считать более дорогую позицию равноценной заменой при жёстком бюджете.

## Готовая еда с предпочтениями — MVP

Для «не острое, не слишком солёное, поменьше жирного» ранжировать только на основании доступных данных. Отсутствующий натрий/соль не равен нулю. Не превращать предпочтение в медицинскую диету. При неполных полях объяснить, что именно подтверждено, а что нет.

## Замена — MVP

Analogs даёт кандидатов, но не гарантирует соответствие требованиям. Проверить размер упаковки, цену за сопоставимую единицу, состав, наличие и бюджет. Предложить diff вместо молчаливой замены.

## Рецепт → закупка — позднее

Загрузить рецепт и ингредиенты; уточнить число порций при отсутствии. Сопоставить ингредиенты с SKU, затем рассчитать закупаемые упаковки. Остатки дома учитывать только из данных пользователя; соль/масло/специи не добавлять автоматически без учёта предпочтений. Нутриенты рецепта на 100 г не равны нутриентам купленной корзины или приготовленной порции.

## Повторить привычную корзину — позднее

Использовать локальную сохранённую корзину. Скопировать в draft, обновить карточки, показать diff цены/наличия/состава. Сводка удалённого заказа не даёт права реконструировать его позиции по догадке. Подготовленная ранее корзина не доказывает факт покупки.

## Скидки — позднее

Начинать с существующих потребностей и находить подходящие предложения, а не создавать потребность из-за процента скидки. Сравнивать цену за одинаковую базу. Плановый запуск выполняется механизмом Hermes только после явной настройки пользователя; результаты без автоматической оплаты.
