# Сценарии

## Уже доступно: локальное намерение

Получить от пользователя product_id и человеческие количества либо существующий
request. Не придумывать идентификаторы. Импортировать, показать, выполнить check.
Объяснить: данные пока не разрешены у провайдера, бюджет/наличие/состав unknown.
Примеры из репозитория содержат условные ID и подходят только для демонстрации.

## Повтор сохранённой корзины

basket show → обсудить изменения → сохранить request → basket import → check.
Старый hash после импорта недействителен. Старые цены не актуальны по умолчанию.
Не восстанавливать товары из сводки истории заказов без состава заказа.
Live refresh пока недоступен.

## После подключения MCP: ужин, рецепт, замены

Эти сценарии являются планом, а не текущими возможностями CLI.

- Ужин: 3–5 кандидатов на позицию, details финалистов, проверка единиц/состава,
  импорт, refresh/check, представление фактов и неизвестного, ссылка по запросу.
- Рецепт: проверить порции и ингредиенты, отделить уже имеющееся, сопоставить
  ингредиенты товарам. Не считать массу рецепта количеством упаковок.
- Аналоги: сравнить новую карточку с исходными ограничениями. Аналог не означает
  подходящий состав или такую же фасовку; изменение бюджета требует пересчёта.
- Строгие исключения: неполный состав → unknown, не pass и не обещание безопасности.
- Итог с доставкой: неизвестная доставка означает непроверенный общий бюджет.

Поиск и создание ссылки в рамках прямого запроса пользователя не требуют
подтверждения каждого шага. Изменение требований, бюджета или разделение
на несколько корзин требует решения пользователя.
При OUTCOME_UNKNOWN остановиться без автоматического повтора.
