# Сценарии

## Первая живая проверка

Doctor --live → product search «молоко» и «хлеб» → get финалистов →
создать request → import → check --refresh → показать оценку и unknown →
link по запросу пользователя. Названия, цены и ID берутся из результатов CLI.
Тестовая ссылка ничего не оформляет. Проверить наличие и итог пользователь
может после открытия ссылки в своём аккаунте.

## Ужин/рецепт

Hermes определяет ингредиенты и порции, затем ищет реальные товары.
Сначала уточнить необходимые количества, если без них нельзя выбрать фасовку.
Не конвертировать граммы в упаковки по названию. В этом CLI можно выбрать число
целых единиц товара «шт» или массу весового товара «кг»; неподдерживаемые единицы
требуют пересмотра запроса. recipe search возвращает ингредиенты и порции;
page=1 без фильтров позволяет узнать доступные ID фильтров. ID товаров в рецепте —
кандидаты: проверь каждый через product get, пересчитай порции и единицы.
Фильтр исключения аллергенов рецепта не заменяет проверку состава товара.

## Повтор сохранённой корзины

Show → при необходимости новый request/import → check --refresh.
Старый состав не гарантирует актуальной цены. orders list требует OAuth и возвращает
только сводки: не выдумывать позиции из сводки. AUTH_REQUIRED не означает пустую историю.
После нового импорта старый hash недействителен.

## Акции и магазины

discount search --type card или quantity: сохраняй условия скидки и не обещай
персональную цену. Текстового запроса у этого tool нет. Для конкретного продукта
используй product search и отдельную проверку карточки.
shop search --page 1: узнай ID региона/города/особенности из meta.filters, затем
передай соответствующие фильтры. Адрес магазина не подтверждает доставку пользователю.
favorite show требует OAuth; любимый продукт не назначается этой командой.

## Замены и строгие ограничения

Analogs → отдельный get → проверка требований → новый request/import/check.
Не повышать бюджет и не разделять корзину без решения пользователя.
При строгом исключении неполные/неоднозначные сведения блокируют ссылку.
Публичное наличие — unknown, а не обещание доставки.
Если бюджет включает доставку, объяснить, что её стоимость не подтверждена.

При REVIEW_REQUIRED покажи актуальные карточки и отличие от прошлого отчёта.
При OUTCOME_UNKNOWN остановиться: не повторять link и не создавать новый basket
для обхода неопределённого исхода.
